# 批量工作流

批次依附一个现有工作台项目保存，但每条视频在 `batches/<batch-id>/<item-id>` 建立独立的项目、素材、副本、确认和任务。网页可以一次选择多个文件、统一包装与速度；导入逐项记录，某个文件失败不阻断其他文件。用户可单独打开项目并修改默认配置。每个视频有独立的素材处理和结果，不把同一场景时间轴、文字或人物资产复制到所有视频。

新建批次可显式勾选全自动本地模式，支持 `none` 和 `remotion-gold`：串行转写、保留原内容、按当前字幕生成暗金标题动画、生成关键帧和本地成片，自动执行范围记录到确认日志，最终待用户听看。已存在字幕时复用。暗金自动版目前是标题动画模板，不是完整语义图解；FredTalk和自由创作仍需Agent。依赖首次安装到包外隔离目录，缺Node/npm或安装失败明确报错，不改其他软件依赖。配置或速度超出批次范围、已有人工场景时停止，不覆盖用户作品。

CLI 以 `--project` 指向批次所在主项目：`batch-create --title ... --packaging ... --speed ...`；`batch-add --batch ID --file PATH`；`batch-list`；`batch-enqueue --item ID --step transcribe|analyze|render`；`batch-run` 消费待执行任务直到队列空或遇到运行/中断状态；`batch-open --item ID --stage project` 打开某条项目。所有命令输出 JSON。网页转写按钮将全部视频加入本地转写队列并启动，云转写不允许在批量步骤静默提交。

一个批次主项目范围内，跨批次只同时运行一个本地步骤；一条明确失败后继续处理队列的下一条。进程意外中断标为 interrupted，不自动重提；Agent 先读子项目 recover 和原任务，再依据明确结果处理，不能把未知任务当失败重新提交。不同主项目尚无全局队列，勿并行启动多个主项目来绕过资源限制。

队列不会代替 Agent：转写后依次读取各项目，完成粗剪及包装策划、创建各自确认请求，用户确认后再按项目制作片段、审看关键帧；待授权后将对应项目渲染入队。渲染入口强制检查粗剪、包装、关键帧确认，云任务仍需单独核验范围与费用；仅 queued/running 重复加入可复用，不把默认预算视为扩大授权。完成后用户可逐条审看和下载。后台进程失联时不声称已完成，也不等待一个已经结束的 Agent 会话自动唤醒。
